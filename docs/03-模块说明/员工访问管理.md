# 员工访问管理

- 模块位置：`packages/platform-modules/workforce-access`
- 类型：业务中立平台模块
- 状态：本地试点基础能力已实现

## 职责

- 保存员工账号目录、稳定 Workforce Person 与 Keycloak User 引用。
- 保存用户名和手机号的规范值、占用历史和显式手机号释放事实。
- 管理 `provisioning`、`credential_pending`、`active`、`disabled`、`failed` 状态。
- 通过 revision、Operation ID 和耐久操作记录提供乐观并发及幂等重放。

## 安全边界

- 不保存密码、凭证、Token、Cookie、Session、邮箱或 Keycloak 必填字段镜像。
- 用户名历史永久占用；手机号只有在不再是当前登录标识且执行显式释放后才能复用。
- Keycloak 管理调用、Session 撤销和 Credential Ceremony 位于应用组合适配器，本模块只保存结果状态和稳定引用。创建账号与管理员重置密码时，BFF 只在当前 HTTPS 请求内接收密码并通过组合适配器直接写入 Keycloak；密码不得进入账号目录、操作收据、审计、日志、Trace、事件或后台 Job。
- 所有写操作先经过服务端授权；客户端 `allowedActions` 不能代替命令授权。

## 持久化与失败

模块独占 `workforce_access` schema。状态变更和操作收据在同一本地事务提交，重复 Operation ID 只有指纹一致时才能重放。外部 Keycloak 失败由应用层通过同一稳定 Operation ID 重试，不得创建重复账号或覆盖并发修改。

创建账号必须提供初始密码。Keycloak 接受密码并启用身份后，账号目录才进入 `active`。重置密码仅允许当前为 `active` 或 `credential_pending` 的账号，成功后撤销既有会话。当前版本化 Realm 策略为 8-64 位可打印半角 ASCII 字符（英文字母、数字、空格和英文符号）；创建、重置、首次登录修改和恢复凭证四个界面必须始终展示可执行的中文规则，并在提交前校验。Keycloak 仍执行最终权威校验；本地 Bootstrap 必须幂等收敛已存在 Realm 的 `passwordPolicy`，配置测试必须阻止 Realm、API 与界面规则漂移。只有稳定错误码 `workforce_password_policy_violation` 可以触发密码策略提醒，其他请求错误不得误报。

普通 CRM 账号的基础访问由 Authorization Policy v2 固定角色 `crm.application-user` 提供，仅含 `crm.application:access` 和 `platform.workbench.shell:read`。Grant 必须绑定唯一有效 Assignment，不能从账号 `active`、部门/岗位名称、Keycloak Role/Group 或前端路由推导。创建时基础 Grant 成功后才允许设置密码、启用 Keycloak 并进入 `active`；调岗关闭旧 Assignment 后迁移 Grant；停用先关闭本地访问再收敛 Grant 和 Keycloak；恢复先建立新 Assignment 与基础 Grant，凭证完成后才激活。`crm.system-administrator` 是独立 Grant，撤销后基础访问不受影响。
