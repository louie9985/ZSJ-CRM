# 认证上下文与会话边界

- 状态：当前实现
- 架构依据：ADR-0034

## 所有权

| 能力 | 所有者 | 不负责 |
|---|---|---|
| Account、登录标识历史、密码凭证、`securityRevision` | `workforce-access` | 组织历史、最终授权、Redis Session |
| Person、Employment、Assignment、部门与岗位 | `organization` | 密码、账号状态、角色 |
| 固定角色 Grant、Permission catalog、`allow/deny` | `authorization` | 登录、Session、组织事实 |
| 认证协调、Cookie/CSRF、Redis Session、限流 | `apps/api` | 跨模块直接查表、持有领域事实 |

`AccountAccessApplicationService` 只通过三个模块的公开端口组合这些事实。账号直接唯一关联 `workforcePersonId`，不存在额外认证主体关联表。

## HTTP surface

员工 `pc` surface 提供：

- `POST /auth/{surface}/login`
- `GET /auth/{surface}/session`
- `POST /auth/{surface}/reauthentication`
- `POST /auth/{surface}/assignment`
- `POST /auth/{surface}/logout`

Cookie 分别为 `__Host-ai_crm_pc_session` 和 `__Host-ai_crm_internal_h5_session`，固定 `Path=/; HttpOnly; Secure; SameSite=Lax` 且为 host-only。所有响应使用 `Cache-Control: no-store`。写请求必须通过同源校验和 `X-CSRF-Token`。

兼职 `part-time` surface 使用独立的 `__Host-ai_crm_part_time_session` Cookie、账号表、密码凭证、限流和审计。兼职只允许 `/part-time/*` 受限入口，不得访问 `/crm/*` 或 `/mobile/*`。

## Session 与失效

Session 存在 Redis，只保存 `accountId`、`workforcePersonId`、`securityRevision`、surface、CSRF、当前 Assignment 和时间戳。idle 30 分钟、absolute 8 小时，同账号同 surface 只允许一个会话。

每次读取 Session 都核对账号为 `active`、`securityRevision` 一致、人员有有效 Employment，且所选 Assignment 仍有效。密码重置递增 revision，所以即使 Redis 删除失败，旧会话也会失败关闭。登录、重新认证、Assignment 切换和敏感操作轮换不透明 credential 与 CSRF。

## 密码与错误

密码采用 Argon2id，参数为 64 MiB、3 iterations、parallelism 1、16-byte salt、32-byte hash。账号不存在时仍验证固定 dummy hash。密码和派生值不得进入日志、审计、Trace、错误或幂等指纹。

对外错误只有 `authentication_invalid_credentials`、`authentication_required`、`authentication_csrf_rejected`、`authentication_rate_limited`、`authentication_dependency_unavailable`。不得通过状态码、消息或明显执行路径差异暴露账号存在性或启用状态。

## 固定角色

`system_administrator` 是全局角色；`application_user` 与 `crm_administrator` 必须绑定有效 Assignment。权限只合并全局角色和当前 Assignment 的角色，不合并其他 Assignment。Permission catalog 受审，不允许 wildcard。

## 非目标

当前不实现 JWT、MFA、自助找回、第三方登录、外部身份、邀请或小程序认证。未来需求必须新增契约与 ADR，不能在当前代码中预留死端点或 Secret。
