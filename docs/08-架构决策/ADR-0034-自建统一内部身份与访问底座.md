# ADR-0034：自建统一内部身份与访问底座

- 状态：已接受
- 日期：2026-08-04
- 适用范围：单一 CRM Web 制品的 PC、员工移动与兼职入口，以及本地开发环境
- 取代：ADR-0004、ADR-0006、ADR-0025
- 部分取代：ADR-0005、ADR-0017、ADR-0018、ADR-0030、ADR-0032、ADR-0033 中关于外部身份提供方、OIDC、外部身份、小程序句柄、认证主体关联、动态策略发布和凭证外包的决定

## 已知事实

当前没有测试或生产环境，也没有必须保留的真实账号、密码、Session、审计或业务数据。当前只有一个 CRM Web 制品，包含 PC、员工移动和兼职入口。人员、Employment、Assignment 及其有效期历史仍是组织事实；账号、凭证、Session 与授权不是组织事实。

## 允许假设

第一版只接受用户名或手机号加密码。密码为 8–64 位可打印半角 ASCII。浏览器只使用 HttpOnly 不透明 Session。初始系统管理员仅由本地受控 bootstrap 创建。整库切换采用本地开发环境空卷重置，不迁移旧数据。

## 禁止假设

不得假设存在 MFA、自助找回、企业微信或微信登录、外部用户、邀请访问、第三方联合身份或非浏览器客户端。不得把姓名、手机号、外部标识、角色名称或前端路由自动解释为身份关联或授权结论。不得为未来 JWT 创建端点、密钥、表或不可达代码。

## 决策

1. 删除 Keycloak、OIDC、外部端和微信小程序认证实现。`workforce-access` 直接以唯一 `workforcePersonId` 关联员工账号并持有密码凭证；`part-time-access` 使用独立账号表和凭证；`organization` 不再持有认证主体关联。
2. API 应用层提供唯一 `AccountAccessApplicationService`。它只通过各模块公开端口协调账号、组织、固定角色、Session 与审计；模块不得跨表查询。
3. 认证 HTTP surface 固定为员工 `pc` 与兼职 `part-time`。员工 PC 和 `/mobile/*` 共用 `pc`；两套身份分别提供登录、Session、重新认证（员工和已实现的敏感操作）、Assignment（仅员工）和登出，使用不同 Cookie、Redis 命名空间、限流和审计。
4. 密码使用 Argon2id：64 MiB、3 iterations、parallelism 1、16-byte 随机 salt、32-byte hash。不存在的标识也验证固定 dummy hash。认证错误不得区分账号不存在、密码错误或账号禁用。
5. Session idle 30 分钟、absolute 8 小时，同账号同 surface 并发上限 1。登录、重新认证、Assignment 切换及敏感操作后轮换。Session 保存账号、`securityRevision`、surface、CSRF、当前 Assignment 与时间戳，不保存密码、密码派生材料或 JWT。
6. Session 以 Redis 持久化。员工 Cookie 为 `__Host-ai_crm_pc_session`，兼职 Cookie 为 `__Host-ai_crm_part_time_session`，固定 `HttpOnly; Secure; Path=/; SameSite=Lax`。账号和登录标识索引使用服务端 keyed digest。
7. 登录按标识与来源地址限流：15 分钟窗口内标识失败 5 次或来源失败 30 次后拒绝。限流、Redis 或必要数据库依赖不可用时失败关闭。
8. 账号状态只有 `active | disabled`。重置密码在短事务内替换 hash 并单调递增 `securityRevision`；旧 Session 即使未从 Redis 删除，也会因 revision 不匹配失效。
9. 固定角色只有全局 `system_administrator` 与 Assignment 绑定的 `application_user`、`crm_administrator`。当前权限是全局角色与当前有效 Assignment 角色的并集，不合并其他 Assignment 的权限。Permission catalog 受审且不允许 wildcard。
10. 动态策略发布、凭证 ceremony、身份同步 Job、外部身份适配、回调、refresh 契约全部删除。JWT 只记录为未来非浏览器客户端的重新决策点。
11. 创建账号在事务外计算密码 hash，再在一个短 PostgreSQL 事务中写入 Person、Employment、Assignment、Profile、Account、Credential、基础角色和审计。任一写入失败全部回滚；密码及派生值不得进入幂等指纹、日志、审计、Trace 或错误。

## 失败与恢复

认证使用固定错误：`authentication_invalid_credentials`、`authentication_required`、`authentication_csrf_rejected`、`authentication_rate_limited`、`authentication_dependency_unavailable`。失败请求不泄露账号状态。历史 migration 不修改；通过新增迁移和本地空卷重置切换。回退必须恢复切换前完整备份与旧应用版本，不能把本地密码 hash 转换为旧身份系统凭证。

## 非目标

本决策不实现 MFA、自助找回、第三方登录、外部用户、邀请、微信小程序、JWT、动态角色/策略编辑器，也不声明生产可用性、SLA、RPO、RTO 或外部运营就绪。兼职客资录入领域功能不在本决策范围，只提供受限工作台壳层。
