# ADR-0029：试点业务模块开发与生产运行验收解耦

- 状态：已接受
- 日期：2026-08-02
- 决策权限：项目负责人
- 适用范围：首个 `packages/domain-modules/` 开发期试点、第一阶段 G4/G5 门及其部署边界
- 依赖决策：ADR-0003、ADR-0007、ADR-0008、ADR-0010、ADR-0011、ADR-0013、ADR-0017、ADR-0022、ADR-0028

## 已知事实

- G4 已以本地组合证据通过：浏览器登录、BFF Session、授权、Form、稳定 FileReference、Task、Outbox/Inbox、隔离 Worker、Audit 和 Trace 均已闭合。
- G5 仍为 `EXTERNAL_BLOCKED`，缺少真实预发布发布/回滚、托管 Sentry/COS/主机证据和恢复演练；这些缺口不影响本地代码正确性，但不能被表述为已完成。
- 项目负责人当前优先验证业务功能，不要求在开始业务开发前建设额外的备份或回滚自动化能力。
- 当前没有已确认的 CRM 领域对象、字段、状态、权限或流程；历史访谈材料不是实现授权。

## 允许的假设

- 一个明确、最小、内部使用的业务纵向流程可以在本地开发环境中复用已通过的公共底座进行验证。
- 试点开发不产生真实业务数据、外部 Provider 调用、预发布或生产流量。

## 禁止的假设

- 不将 G4 或本 ADR 解释为 G5、预发布、生产、备份、回滚、恢复、Sentry、COS 或主机安全已验收。
- 不因“试点”跳过业务 Owner、规则、权限、审计、幂等、迁移、合同或测试。
- 不从访谈材料推断 Lead、Customer、Order、Settlement 或其他领域对象、字段、状态、SLA、审批和角色。
- 不将领域模块直接连接 Keycloak、Flowable、RabbitMQ、Redis、对象存储或其他模块数据库。

## 决策

1. G5 保留为外部运行与第一阶段正式签收门，但不再阻止一个开发期试点领域模块的本地实现。
2. 试点启动前必须满足 [试点业务模块启动清单](../04-工程手册/试点业务模块启动清单.md) 的全部“开始编码前”项目，并由项目负责人确认范围。未选择具体模块时，不创建空包、表、接口或占位状态机。
3. 同一时间只允许一个开发期试点模块。第二个业务模块须在首个模块的模块级验收、独立 Review 和范围复盘后另行确认。
4. 试点只能在本地开发环境运行，使用合成、脱敏或明确授权的测试数据；禁止接入真实外部 Provider、发布到共享测试环境、预发布或生产。
5. 仅在本地、无真实业务数据的开发期试点中，不新增备份、回滚、PITR 或主机恢复自动化功能。现有 OPS-01/OPS-02 门和制品保留，且在任何业务模块进入预发布或生产前必须完成相应外部证据。
6. 每个试点命令必须通过公共 Organization/Authorization、审计和平台 SDK/合同边界；需要异步、Task、通知、Form 或文件能力时，只使用已确认的公共合同。新增业务合同先于实现评审。

## 开始编码门

开始实现前，项目负责人须确认并记录：

1. 模块名称、Owner、唯一业务对象和最小纵向流程。
2. 对象状态机、允许迁移、撤销/退回/重开/历史保留规则。
3. 内部主体、功能权限、数据范围和拒绝行为。
4. 数据 Owner、模块数据库 schema、迁移回退指导和跨模块交互合同。
5. HTTP/Event 合同、审计事件、幂等键、并发/重复/失败恢复语义。
6. 是否使用 Form、File、Task、Notification、Workflow 或外部访问；未确认的能力保持不接入。
7. 本地验收场景、测试数据边界和明确的“不发布到非本地环境”限制。

## 影响与接受风险

- 可以更早验证一条真实业务纵向流程，减少公共底座等待对功能学习的阻塞。
- 本地试点数据和运行环境不具备已演练的恢复能力；该风险仅在不承载真实业务数据、不对外发布的范围内接受。
- 试点代码仍可能需要在 G5 外部环境验收中补充运行、恢复和遥测证据，不能因本地测试通过而直接上线。
- 业务范围会受到单模块、已确认规则和现有公共能力的约束；未确认的外部访问、Provider、审批路线、通知角色和 SLA 必须另行决策。

## 备选方案

### 等待 G5 后再开始业务开发

运行风险最低，但当前缺少受控环境和治理前置条件，会延迟业务功能验证，故不采用。

### 取消所有备份、回滚和恢复要求

会把开发期风险扩展到真实数据与生产运行，也会违背现有部署和数据治理边界，故不采用。

### 不设范围地并行开发多个业务模块

会在业务规则未确认时放大架构和数据模型漂移，故不采用。

## 替换条件

- 首个试点完成模块级验收后，项目负责人可用新 ADR 决定扩大到多个领域模块。
- 任何试点要进入共享测试、预发布或生产，必须先完成 G5 对应外部证据，并另行确认该模块的发布与数据治理条件。
