## 1. 补充说明总论：从AI-CRM到AI公司经营操作系统

> **核心判断** V3.1已经能支撑客户生命周期主链路，但如果公司目标是从40人增长到200人、从年营收千万增长到过亿，系统不能只停留在CRM层面，必须升级为"AI驱动的公司经营操作系统"。

V3.1主文档重点解决的是：客资如何进入系统、销售如何承接、订单如何履约、财务如何审核、学生服务如何交付、学习规划师如何复购、就业指导如何承接、老板大盘如何看业务结果。这个框架是正确的，但它更偏"客户经营前中台"。

一家200人规模、月营收1000万到1600万、净利润目标15%到30%的公司，还需要补上经营底盘：产品利润、管理会计、法务合规、数据安全、AI治理、渠道伙伴、企业服务、品牌公关、知识管理、PMO流程治理、投融资可审计报表、后勤资产与内控审计。

因此，本补充版的定位不是增加更多花哨功能，而是回答三个问题：第一，公司做大后系统还缺哪些经营模块；第二，不同营收阶段需要多少人、多少客资、多少销售和多少交付能力；第三，如果按200人、月营收1600万测算，部门编制、薪酬包、人效、成本率和利润目标是否成立。

### 系统升级后的总体边界

| 层级 | 原AI-CRM主要解决 | 升级后AI经营操作系统必须增加 |
|---|---|---|
| 客户层 | 线索、客户、订单、学习、复购、就业 | 客户隐私授权、生命周期价值、客户风险、客户成功、NPS/满意度、企业客户与伙伴客户 |
| 业务层 | 新媒体、销售、报名、教务、考务、就业 | 产品经营、渠道伙伴、企业服务、品牌公关、流程PMO、知识培训 |
| 财务层 | 收款、退款、订单审核、佣金结算 | 管理会计、产品利润表、渠道ROI、现金流预测、合同负债、发票税务、投融资报表 |
| 治理层 | 质控、投诉、绩效统计 | 法务合规、数据安全、AI治理、内控审计、权限回收、证据链 |
| 组织层 | 岗位待办、绩效指标、主管大盘 | 岗位饱和度、人力预测、干部梯队、培训认证、组织健康、跨部门连带责任 |

### 升级后的开发原则

第一阶段不要求把所有模块做深，但底层数据字段必须预留，尤其是产品SKU、价格、成本、毛利、合同、授权、权限、AI调用、退款、佣金、伙伴、企业客户。

所有新增模块都必须回到业务闭环：能降低风险、提高利润、提升人效、减少返工、支撑复制，而不是为了系统复杂而复杂。

法务、财务、税务、数据安全、AI治理等规则需要由对应负责人和外部顾问最终确认，AI-CRM只负责流程留痕、权限控制、审批记录和数据统计。

AI应用开发部开发时，要把这些模块理解为V3.1主链路的经营底盘，不应与销售线索功能混在同一个页面里。

## 3. 新增模块的系统功能要求

### 3.1 产品SKU与价格中心

| 项目 | 说明 |
|---|---|
| 核心对象 | 产品、班型、服务包、组合套餐、畅学卡、就业产品、企业服务、AI工具、轻创项目。 |
| 必填字段 | 产品名称、产品类型、标准价、最低价、可优惠范围、服务期、学习期、成本结构、适用人群、交付部门、负责人。 |
| 权限规则 | 销售只能在授权价内成交；低于最低价必须发起特批；组合套餐必须由市场项目负责人或更高层确认。 |
| 财务字段 | 考试成本、教材成本、导师成本、平台成本、客资成本、销售佣金、复购佣金、预计毛利、实际毛利。 |
| 大盘指标 | 产品营收、毛利、退款率、投诉率、通过率、复购率、就业结果率、生命周期价值。 |

### 3.2 管理会计与利润中心

| 项目 | 说明 |
|---|---|
| 核心目标 | 让老板看到不是谁卖得多，而是谁卖得健康、谁贡献利润、哪个产品/渠道/班种值得继续投。 |
| 利润维度 | 产品利润、渠道利润、销售组利润、学习规划师复购利润、就业产品利润、企业服务利润、轻创项目利润。 |
| 关键指标 | 营收、退款、获客成本、交付成本、佣金、导师结算、发票税费、毛利、经营净利、现金回款。 |
| 预警规则 | 低毛利订单、异常低价、退款率异常、渠道ROI下降、复购毛利不足、合同负债过高。 |

### 3.3 法务合规与经营风控中心

| 项目 | 说明 |
|---|---|
| 核心风险 | 证书效力夸大、包过承诺、就业兜底承诺、健康/心理/中医宣传边界、直播话术违规、合同不完整。 |
| 系统动作 | 合同模板管理、特殊承诺审批、话术/素材抽检、投诉证据链、重大争议法务审核。 |
| 审批对象 | 特殊低价、特殊退款、就业兜底、高额订单、代理加盟、企业合作、外部导师合作。 |
| 证据链 | 销售跟进记录、聊天截图、合同、付款记录、服务记录、学习记录、考试记录、投诉处理记录。 |

### 3.4 数据安全与AI治理

| 项目 | 说明 |
|---|---|
| 数据分级 | 普通业务数据、客户个人信息、敏感业务信息、财务信息、员工绩效信息、企业客户信息。 |
| 权限控制 | 岗位可见、主管可见、跨部门授权可见、脱敏可见、导出需审批、离职自动回收。 |
| AI治理 | AI调用日志、输入脱敏、输出抽检、人工确认、Prompt版本管理、AI建议不得直接替代最终审批。 |
| 开发要求 | 所有查看、导出、修改、删除、AI调用都要有日志；关键数据要可追溯到人、时间、原因和流程。 |

### 3.5 渠道伙伴与企业服务

| 项目 | 说明 |
|---|---|
| 伙伴类型 | 轻创学员、兼职客资、兼职主播、代理、分校、外部导师、就业企业、企业合作方。 |
| 伙伴字段 | 类型、等级、协议、授权范围、结算规则、贡献营收、毛利、投诉、信用分、风险标签。 |
| 企业端字段 | 企业名称、联系人、岗位需求、培训需求、合同、回款、人才匹配、招聘结果、复购机会。 |
| 风控重点 | 虚假客资、私单、抢归属、乱承诺、企业岗位真实性、导师交付质量、加盟区域冲突。 |

### 200人模型成立的10个条件

- 首购不能长期超过总收入60%，否则获客和销售成本过重。
- 复购、畅学卡、就业指导、企业服务、AI工具合计最好超过40%。
- 销售人均月业绩必须稳定在20万以上。
- 学习规划师人均复购必须稳定在10万-15万。
- 有效客资成本必须持续下降，不能长期靠高投流硬砸。
- 退款率必须控制在5%-8%以内。
- 产品综合毛利率必须稳定在60%以上。
- AI至少要节省25-40个等效人力，否则200人很难做到30%净利。
- 财务必须能按产品、渠道、部门、人员核算利润。
- 法务合规、质控、数据安全必须前置，不然后期一次大风险就可能吃掉数月利润。

## 9. AI赋能降本增效目标

| 场景 | AI目标 | 等效收益 |
|---|---|---|
| 客资判重/评级/分配 | 自动完成80%以上 | 少配2-4名客资运营，减少重复客资和分配争议 |
| 销售跟进摘要/提醒/话术 | 单销售承接提升20%-30% | 少招8-12名销售，降低漏单和回访遗忘 |
| 报名资料OCR/合同校验 | 订单处理效率提升40% | 少招3-5名报名专员，减少资料错误 |
| 学习规划AI助手 | 学规承接提升25%-35% | 少招6-10名学习规划师，提高复购机会识别 |
| 财务自动对账/佣金计算 | 结算效率提升50% | 少招2-3名财务，降低结算错误 |
| 质控通话/聊天抽检 | 抽检覆盖从人工抽样提升到半自动全量 | 少招3-5名质检，提前识别过度承诺 |
| 人力绩效自动统计 | 绩效统计自动化80% | 少招2-3名人力运营，让人力转向组织诊断 |
| 老板经营预警 | 每日异常自动总结 | 提前发现利润、现金流、退款、投诉和人员超载问题 |

### AI开发约束

- AI可以给建议、生成摘要、识别异常、推动提醒，但不应直接替代财务审核、质控判责、法务意见、绩效最终确认。
- 涉及客户个人信息、员工绩效、财务、合同、投诉、健康/心理/中医相关内容时，必须保留人工确认和操作日志。
- 每个AI功能都要有"节省时间、提升转化、减少错误、降低成本、降低风险"中的至少一个可量化目标。
- AI功能上线后要进入经营大盘，持续观察使用率、准确率、误报率、节省工时、用户反馈和业务结果。

### 10.3 风险提示

- 月营收1600万、净利润15%-30%的模型成立前提是复购、就业指导、企业服务、AI工具、轻创生态共同贡献收入；若长期只靠首购招生，净利率会被获客和销售成本压低。
- 人力成本一旦长期超过营收30%，公司会进入高收入低利润状态，必须通过AI提效、产品毛利提升和组织人效改善解决。
- 学习规划师是复购核心，但不能让其承担无限杂事；学务支持、工单、AI助手和质控边界必须清楚。
- 法务、税务、隐私、AI合规属于专业领域，本文件提供系统建设方向，最终规则需要外部律师、税务顾问和公司负责人确认。
- 本文件测算为经营模型，不是财务审计报告；正式预算需要结合真实工资、社保、公积金、税率、场地、投流、佣金和退款数据重新测算。
