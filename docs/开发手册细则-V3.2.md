# 开发手册细则 V3.2

> 读者：3名全栈开发 + AI编码代理。总纲第0章《架构宪法》AP-01~21为最高约束，本手册是其工程落地。
> **本手册第1~4章内容必须写入AI编码代理的系统提示。**

## 1. 仓库与协作

### 1.1 monorepo 结构
```
crm/
  packages/
    shared-core/        # API client(OpenAPI生成)、类型、Zustand store、业务hooks、权限判断、校验schema(zod)
    web/                # React 19 + HeroUI Pro（CollectUI）+ Tailwind CSS 4，只写视图
    mobile/             # 内部移动端（企微工作台 H5，Taro，CR-11），只写视图
    h5-partner/         # 外部提交端（Taro，出 H5 + 微信小程序，CR-10），只写视图
  apps/
    server/             # NestJS，按业务模块纵切
  docs/                 # 总纲/PRD/事件契约表/本手册
  tools/                # 造数脚本、迁移工具
```
pnpm workspace + Turborepo。`web/mobile/h5-partner` 禁止直接写业务逻辑——逻辑一律下沉 shared-core，评审见到端内写校验/计算/权限判断即打回。

### 1.2 server 目录（按模块纵切，禁止技术层横切）
```
apps/server/src/
  platform/           # P1~P6：auth, org, permission, ownership, dedup,
                      #        task, approval, scheduler, notify, alert,
                      #        dict, config, audit, timeline, import-export,
                      #        attachment, event-bus, metrics, integration, ai-gateway
  modules/
    m1-org/ m2-person/ m3-catalog/
    m4-lead/ m5-sales/ m6-order/ m7-enroll/
    m8-student/ m9-finance/ m10-qc/ m11-ticket/
    m12-workbench/ m13-dashboard/
```
依赖规则（ESLint boundary 规则强制，CI拦截）：
- `platform/**` 禁止 import `modules/**`
- `modules/mX` 禁止 import `modules/mY`（跨模块只走事件或platform服务）
- 跨模块数据引用只存ID，禁止跨模块外键JOIN写业务逻辑（查询聚合在m13或BFF层做）

### 1.3 分支与提交
- trunk-based：main + 短生命feature分支（<2天），PR合入
- PR门禁：lint + tsc + 单测 + boundary检查全绿 + **1名人工评审**
- 人工评审重点（对照清单）：金额计算、归属变更、状态流转、权限判断、迁移脚本——这五类AI生成代码**必须逐行人读**
- commit：`feat(m4): xxx` / `fix(platform/task): xxx`，关联工单号

## 2. 后端规范

### 2.1 API
- REST，路径 `/api/v1/<module>/...`
- 统一响应包：`{ code, message, data, trace_id }`；错误码表见附录，业务错误码 `<模块号><3位>`（如 M6 订单终态冲突=6001）
- 所有写操作接受 `X-Request-Id` 幂等键（AP-18）：服务端以 (幂等键+端点) 去重，重复请求返回首次结果
- 分页统一 `page/page_size/total`；列表默认按数据范围拦截器过滤（AP-02）
- OpenAPI 由装饰器自动生成 → CI产出 shared-core 的 TS 类型与 client（AP-15：接口变更=类型变更=前端编译期发现）

### 2.2 数据库
- Prisma Migrate；**迁移脚本人工评审必过**，禁止AI直接生成后合入
- 命名：表snake_case单数；金额 `*_cents bigint`；时间 `*_at timestamptz`；枚举用varchar+字典校验（便于L2配置扩展），核心状态机枚举例外用pg enum（防脏值）
- 软删除 `deleted_at`；物理删除仅限管理员数据修正流程
- 统一审计字段由Prisma中间件自动填充；关键表变更自动写audit_log（AP-12）
- 敏感列（phone/id_card）应用层加密，另存hash列做等值查询与判重

### 2.3 状态机与并发
- 状态流转唯一入口：`StateMachineService.transition(object, from, to, actor, reason)`——校验合法流转表、终态保护（AP-07）、写timeline、发事件。业务代码直接update status字段=打回
- 抢单/接单并发：`UPDATE ... WHERE id=? AND status='pending' AND owner IS NULL` 乐观锁，影响行数=0即已被抢，返回业务错误码而非500
- 定时任务〔CR-01〕：RabbitMQ 延迟消息触发（延时/倒计时）+ Redis 分布式锁 + job 幂等（以DB状态为准判断是否执行）+ 失败重试3次后进 DLQ 死信告警（AP-11）

### 2.4 事件
- 发布：业务事务内写 event_store（同库同事务，保证业务与事件原子性），事务提交后由 dispatcher 投递给订阅者
- 消费：消费者自管 event_cursor，处理幂等（以 event_id 去重）
- 事件字段变更必须走《事件契约表》升版流程

### 2.5 金额与结算
- 全链路整数分（AP-19）；分账不平差额（分佣比例除不尽）归入明确的余数规则（大头给成交人，写死进单测）
- 佣金台账只增不改：状态迁移=新增流水行，余额=聚合计算（对账友好）

## 3. 前端规范

- 权限：路由/菜单/按钮全部读 `/me/permissions`；**任何本地硬编码角色判断打回**（AP-16）
- 状态：Zustand store 在 shared-core；服务端状态用 TanStack Query（缓存键规范：`[module, resource, params]`）
- 表单校验：zod schema 在 shared-core，Web/移动端共用；后端用同一schema二次校验（single source）
- 列表页/详情页必须用 P7-2/P7-3 统一组件，禁止每页手搓
- 页面状态可恢复：筛选条件进URL query（Web）/路由参数（移动端 Taro）（AP-17）
- 移动端专项〔CR-11〕：内部端（企微 H5）与外部端（小程序+H5）均用 **Taro + NutUI-React + Tailwind token + Lucide**；路由用 Taro Router；弱网下写操作必带loading+幂等键防连点；企微应用消息深链→对应详情页路由表；内部端企微 OAuth 免密登录、账号密码为根。~~原 RN/react-navigation/极光 JPush 口径已随 App 废弃~~
- 禁止mock长存：联调用staging真实接口；确需mock标注`// MOCK-TODO(工单号)`，CI每周报告清单

## 4. AI 编码纪律

1. 系统提示固定包含：架构宪法AP-01~21全文 + 本手册1~4章 + 目标模块的PRD节选 + 事件契约表相关行
2. AI生成物分级：
   - **绿**（UI布局、DTO、样板CRUD、测试脚手架）：评审走查即可
   - **红**（金额/佣金、Ownership、状态机、权限、审批、迁移脚本、定时任务）：逐行人读+单测强制，测试先行（人写用例断言，AI补实现）
3. 提示词中禁用真实客户数据（附录B敏感字段全列）；造数用 tools/seed 脚本
4. AI改动跨模块边界（新增事件/改platform接口）时，必须先在M11开工单，产品负责人批准后再生成代码
5. 每个模块完成后跑一次"AI自审"：把宪法条款作为检查清单让AI对自己的diff逐条自查并输出报告，人工复核报告

## 5. 测试与质量

| 层 | 范围 | 要求 |
|---|---|---|
| 单测 | shared-core全部；server红类代码 | 红类覆盖率≥90%；分账余数、状态终态保护、时区/夜间SLA必有用例 |
| 集成测 | 五条E2E主链路（总纲8.3） | staging环境CI夜跑 |
| 双端人工 | 交互验证清单（每模块PRD的AC） | 真机各一台iOS/Android |
| 影子周 | W7一个销售组+报名服务双跑 | 并发抢单、退款回滚、夜间SLA实测 |

时区规定：服务器/DB统一UTC存储，展示按 Asia/Shanghai；"当日下班前""90日"等业务日界线一律按 Asia/Shanghai 计算（写进公共 dateutil，禁止业务代码自算）。

## 6. 环境与发布

- 环境：dev（本地docker-compose）/ staging / prod；配置走env+配置中心，密钥不入库不入git
- 发布：main合入自动部署staging；prod发布=手动触发+发版清单（含：迁移脚本核对、config_param新增项核对、事件契约版本核对）
- 备份：PG每日全量+WAL归档，恢复演练在影子周前做一次
- 回滚：镜像回滚+迁移脚本必须可逆（不可逆变更分两步发）
- 围栏期：8/18起只修不加（切换前两周），新需求一律进4.0池
