## 1. 总体开发价值、系统意义与开发要求

AI-CRM 是中世健教育从培训公司升级为健康职业人才生态平台的底层经营系统。它不是单纯记录客户，而是把客资、销售、报名、财务、学习服务、复购、就业、人才库、企业合作、人力绩效、质控监督串成一个可追踪、可预警、可复盘、可扩张的业务操作系统。

### 1.1 系统开发价值

- 客户资产沉淀：避免客户信息散落在个人微信、表格、部门局部工具中。
- 流程可控：让客资、销售、订单、履约、财务、服务、复购每一步都有状态和责任人。
- 岗位赋能：每个岗位打开系统即看到今日待办、目标差距、预警、操作入口和AI建议。
- 管理透明：主管看团队过程，老板看客户全生命周期漏斗和真实经营质量。
- 绩效可依：系统自动记录任务、业绩、质量、投诉、协同，供人力和主管复核使用。
- 生态扩展：为轻创学员、兼职客资、就业导师、企业、人才库、分校/代理预留身份和数据结构。

### 1.2 开发要求

- 第一版必须两个月内上线可运营 MVP，优先跑通客户全生命周期主链路。
- 每个岗位必须有独立工作台，不允许只做一个通用列表让员工自己找工作。
- 每个关键流程必须有发起人、执行人、审核人、确认人、监督人和状态追踪。
- 每个关键字段必须明确由谁采集、谁审核、谁可见、谁能修改。
- 每个模块必须支持操作日志、信息补充、临时提醒、超时预警。
- 系统不追求第一版功能大而全，但权限、状态、日志、主链路不能偷懒。

### 1.3 给全栈开发团队的理解方式

开发团队应按"业务对象 + 角色权限 + 工作台 + 流程状态 + 数据大盘"的方式理解系统。不要只从数据库表和页面菜单出发，而要先理解每个岗位在业务链路中承担什么责任、拥有什么权限、产出什么数据、接受谁监督。

## 4. 销售转化中心详解

| 项目 | 说明 |
|---|---|
| 部门价值 | 承接公司所有未成交客资，完成首购咨询和成交，是营收转化的核心部门。 |
| 部门职责 | 接单、首触、添加企微、需求判断、方案推荐、跟进、成交录单、客户档案补充。 |
| 部门关键指标 | 成交金额、成交率、接单率、首触率、添加成功率、客单价、7/30/90日成交率、人均业绩。 |

## 15. 老板、总监、主管、员工四级大盘体系

|---|---|---|
| 老板大盘 | 客户全生命周期漏斗、今日/周/月业绩、客资有效率、成交、报名、财务、入学、学习规划、复购、退款、投诉、毛利预留、人效 | 决策、资源调配、发现公司级卡点 |

## 19. 岗位界面开发统一规范

每个岗位都需要独立操作界面，但界面结构应统一，降低开发和培训成本。建议采用"顶部指标卡 + 今日待办 + 主业务列表 + 右侧提醒/AI建议 + 状态追踪"的标准布局。

| 区域 | 内容 | 开发要求 |
|---|---|---|
| 顶部指标卡 | 今日/本周/月核心KPI、目标差额、排名或异常 | 不同岗位指标不同，可配置 |
| 今日待办 | 系统自动生成任务、人工任务、临时提醒、待审批 | 必须支持完成、延期、转交、备注 |
| 主业务列表 | 客资/客户/订单/学员/工单/岗位/企业等 | 支持筛选、排序、状态、批量操作 |
| 详情页 | 主档案、时间线、记录、订单、服务、工单、日志 | 按权限展示字段 |
| 右侧辅助栏 | 提醒、预警、AI总结、话术/知识库、相关流程 | 第一版AI可简化为规则建议 |
| 状态追踪 | 待处理、处理中、待补正、已完成、已超时 | 所有跨部门动作必须有状态 |
| 数据归档 | 操作日志、信息补充、附件、证据 | 关键动作不可无痕修改 |

### 19.1 每个岗位界面必须回答的问题

- 我今天必须做什么？
- 什么快超时了？
- 我离本日/本周/月度目标差多少？
- 我提交的客资、订单、工单、复购、投诉现在到哪一步？
- 我有哪些信息需要补充？
- 哪些问题影响我的绩效或收益？
- 系统给我的改进建议是什么？
- 主管或质控对我的反馈是什么？

## 20. 给AI应用开发部的开发落地建议

- 按业务模块Owner分工，不要三个人都只做零散任务。建议：A负责客资+销售，B负责订单+财务，C负责学生服务+大盘+流程任务。
- 每天用业务规则答疑池记录不懂的问题，老板/产品负责人统一答复，避免微信碎片化。
- 每周必须做业务验收，拉对应部门负责人参加，不要只做技术自测。
