## 1. 目标与非目标

**目标**
- 账号密码为**唯一根身份**，任何端可直接登录，不依赖任何第三方绑定。
- 企微 userid（内部）/ 微信 openid（外部）作为**可选绑定的快捷入口**，实现免密快进。
- 支持"首次触达自动引导绑定"的登录流程。

**非目标（本工单不做）**
- 企微通讯录同步、微信生态其它能力（只做 OAuth 免密登录 + 绑定）。
- 多 provider 并存（明确一账号至多绑一个 provider——内部只企微、外部只微信，无交叉）。
- 账号密码本身的认证机制（已在 CR-03 定稿：JWT access + Redis refresh）。

## 3. 表设计：`account_oauth_binding`（已定稿 2026-07-08）

> 字段级设计已定稿并回写 PRD-B1 §1.1；**落库仍须走 §9 迁移脚本人工评审**（禁 AI 直接合入）。

| 字段 | 类型 | 约束 / 说明 |
|---|---|---|
| `id` | uuid | PK |
| `account_id` | uuid | FK → account.id，NOT NULL |
| `provider` | enum | `wecom` / `wechat`，NOT NULL |
| `external_id_enc` | varchar | 应用层加密：企微=userid、微信=openid（DEC-2） |
| `external_id_hash` | char(64) | sha256(provider + external_id)，用于唯一约束与等值查询 |
| `union_id_enc` | varchar null | 微信 unionid（加密），企微为 null（DEC-4） |
| `status` | enum | `active` / `unbound`，NOT NULL |
| `bound_at` | timestamptz | 绑定时间 |
| `bound_source` | enum | `first_login` / `user` / `admin`（绑定来源，审计用） |
| `unbound_at` | timestamptz null | 解绑时间（软删，留痕） |
| `unbound_by` | uuid null | 解绑操作人 |
| + 统一审计字段 | | created_at / updated_at 等 |

**唯一约束（防串号，红类关键）**
- `UNIQUE (external_id_hash) WHERE status='active'`
  → 一个企微 userid / 微信 openid 全局只能绑到**一个**平台账号（防止他人把你的企微身份绑到他账号）。
- `UNIQUE (account_id, provider) WHERE status='active'`
  → 一账号同一 provider 至多一个生效绑定（对齐"一账号至多绑一个第三方"）。

**索引**
- `(account_id)`：查某账号的绑定。
- 上述两个 partial unique 索引。

**若 DEC-1 选 (a)**：迁移时删除 `account.wecom_userid` 字段；已有数据迁进绑定表（迁移脚本人工评审）。

## 4. API 端点设计（已定稿 2026-07-08）

统一前缀 `/api/v1/auth/`，写操作支持 `X-Request-Id` 幂等键（AP-18）。

### 4.1 内部（企微）

| 端点 | 方法 | 入参 | 出参 | 说明 |
|---|---|---|---|---|
| `/auth/wecom/login` | POST | `{ code }` | 已绑→`{access, refresh}`；未绑→`{need_bind:true, bind_ticket}` | 后端用 code 调企微换 userid，查绑定 |
| `/auth/login` | POST | `{ phone, password, bind_ticket? }` | `{access, refresh}` | 账号密码登录；带 bind_ticket 则登录成功后完成绑定 |
| `/auth/bind/wecom` | POST | `{ code }`（需登录态） | `{ok}` | 已登录用户主动绑定 |
| `/auth/bind/wecom` | DELETE | （需登录态 / 管理员） | `{ok}` | 解绑（DEC-3） |

### 4.2 外部（微信）

| 端点 | 方法 | 入参 | 出参 |
|---|---|---|---|
| `/auth/wechat/login` | POST | `{ code }` | 同企微：已绑免密 / 未绑返回 bind_ticket |
| `/auth/login` | POST | `{ phone, password, bind_ticket? }` | 复用同一端点 |
| `/auth/bind/wechat` | POST / DELETE | 同上 | |

## 5. 首次触达时序（按已拍板：先弹授权 → 未绑引导账号密码）

```
企微工作台打开内嵌 H5
  → 前端经企微 OAuth / JS-SDK 拿 code
  → POST /auth/wecom/login { code }
       后端: code → 换取 userid → 查 account_oauth_binding(wecom, userid, active)
       ├─ 命中  → 200 { access, refresh }        ← 免密快进
       └─ 未命中 → 200 { need_bind, bind_ticket } ← bind_ticket 承载「已验证的 userid」
                    → 前端展示账号密码登录页
                    → POST /auth/login { phone, password, bind_ticket }
                         后端: 验证账号密码 → 校验 bind_ticket → 写绑定表 + 审计 → 签发登录态
                    → 下次再打开 /auth/wecom/login 直接命中 → 免密
账号密码直登（不经企微）: POST /auth/login { phone, password } 恒可用（根身份兜底）
```

微信端（外部）时序同构，把 `wecom` 换成 `wechat`、`userid` 换成 `openid`。

## 6. 安全考量（红类必审）

- **`bind_ticket` 是安全命脉**：服务端签发的一次性短 TTL 令牌（存 Redis，含**服务端已验证的** external_id + provider）。绑定时 external_id **只能来自 ticket，绝不信前端直接传的 userid/openid**（AP-03）——否则攻击者可传任意 userid 绑到自己账号。TTL 建议 5–10 分钟（待定）。
- **OAuth `state` 参数**防 CSRF。
- **`(external_id_hash) active 唯一**防串号（见 §3）。
- **绑定/解绑写审计**（AP-12）：account_id、provider、external_id（掩码或 hash）、action(bind/unbind)、bound_source、operator、ip、time。**不记录明文凭证/token**。
- external_id 加密存储（DEC-2），日志不落明文（对齐 AP-14 与 Pino redact 口径）。
