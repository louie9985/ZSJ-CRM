# 事件契约表 V3.0（独立受控文档）

> 变更规则：任何事件的新增、重命名、字段变更，必须走 M11 需求工单 + 产品负责人审批后修订本表并升版本号。
> 事件=模块间API。禁止业务模块绕过事件直接读写其他模块的表（AP-21）。
> 通用骨架：`event_id, event_type, biz_ref_type, biz_ref_id, occurred_at, actor_id, payload(jsonb), config_version`

## 命名规范
`<域>.<对象>.<动作过去式>`，全小写点分。动作必须是"已发生的事实"，不是指令。

## 消费原则
1. 消费者自管位点（event_cursor），至少一次投递，消费端幂等
2. 同一事件多订阅方互不阻塞；失败重试不影响其他消费者
3. M13所有指标只从本表事件计算，发现"表里查得到但事件里没有"=发布方bug，按事故处理

- **2026-07-08〔CR-11〕移动端由 App 改小程序/H5——本表已核对，无需新增或修改任何事件。** CR-11 只改通知的**触达通道**（原 App 推送 → 内部企微应用消息 / 外部只站内），而通知本就是既有事件（lead.assigned、ownership.changed 等）的**消费端**产物；触达通道属消费端实现细节，非新业务事实，事件契约不变（AP-21：通道变、事件流不变）。登录绑定为 platform 认证行为，走 audit_log 而非 event_store，同样不产生跨模块事件。若后续实现中发现确需新增触达相关事件，另开 M11 工单升版。
