## 1. 项目背景与系统定位

中世健教育是一家成人健康职业教育培训机构，当前员工约 40 人，年营收约 1000 万，未来目标是支持年营收过亿、员工规模约 200 人，并逐步发展为中国健康职业发展领域最具影响力的生态平台。

公司业务覆盖营养师、心理咨询师、健康管理师、慢病管理、执业药师、中医适宜技术、学历提升、技能实操、就业指导、轻创博主等多个项目，客户生命周期不止于首购报名，而是延伸到学习、考试、证书、技能、复购、就业、人才库、企业合作和轻创/代理生态。

> **系统定位**：AI-CRM 不是普通销售 CRM，而是客户全生命周期经营系统。第一版先跑通从客资到销售、订单、报名、财务、学生服务、复购记录、老板大盘的主链路；后续再扩展就业事业部、人才库、企业端、题库工具和健康从业者客户管理平台。

### 1.1 当前关键痛点

- 客户信息分散在表格、企业微信、个人微信和现有 CRM 中，无法形成统一客户资产。
- 销售接单、首触、回访、成交过程不够透明，主管难以及时辅导和纠偏。
- 报名履约、财务审核、学员分班、学习规划交接依赖人工和表格，责任边界不清。
- 考试、证书、缓考、补考、延期节点容易遗漏，服务质量无法稳定复制。
- 复购要求高，但复购机会识别、职业种草、畅学卡化缺少系统化流程。
- 老板和管理层缺少客户全生命周期漏斗，无法一眼看到客户卡在哪个环节。
- 未来轻创学员、兼职客资、外部导师、企业端、分校/代理等生态角色会进一步增加复杂度。

### 1.2 第一版边界

MVP 两个月上线版本必须优先解决公司内部主链路经营闭环，不追求完整生态平台。就业、人才库、企业端、完整绩效、完整结算、AI题库、健康从业者外部工具等进入二期或后续产品线。

## 2. 建设目标与 MVP 成功标准

### 2.1 建设目标

- 统一客资入口，支持新媒体、轻创、兼职、转介绍、直播、线下、就业引流、企业、代理等多入口录入。
- 统一客户主档案，支持一人多身份、一主档案多部门补充、敏感信息分权可见。
- 跑通销售转化流程，形成接单、首触、回访、有效判定、成交录单、排名和主管辅导闭环。
- 标准化订单、报名履约、财务审核、学员生成、学习规划师分配。
- 建立学习规划师服务记录、职业种草、复购机会和复购订单提交基础能力。
- 建立老板客户全生命周期经营漏斗，看清客资、有效、成交、报名、财务、入学、学习规划、复购等节点。
- 建立任务、提醒、信息补充、操作日志、责任记录，为后续绩效、质控和AI分析打基础。

### 2.2 两个月上线验收标准

| 序号 | 验收标准 |
|---|---|
| 1 | 新客资能够从多个入口进入系统，并完成判重和分配。 |
| 2 | 销售能在系统完成接单、首触、跟进、有效判定、成交录单。 |
| 3 | 报名履约能在系统审核订单、驳回、补正、记录合同/开课/拉群/教材/分班状态。 |
| 4 | 财务能在系统完成到账审核、金额核对、通过/驳回、7日退款期状态记录。 |
| 5 | 订单通过后能生成学员档案并分配学习规划师。 |
| 6 | 学习规划师能记录首次触达、学习规划、服务记录、职业种草基础状态和复购机会。 |
| 7 | 老板能查看客户全生命周期漏斗，并按今日/本周/本月、部门、产品、渠道筛选。 |
| 8 | 核心岗位打开系统后能看到今日待办、超时提醒、临时提醒、状态追踪。 |
| 9 | 关键动作有操作日志，能追溯发起人、执行人、审核人、确认人、监督人。 |
| 10 | 权限控制不泄露敏感信息，财务、隐私、质控、绩效相关字段按权限展示。 |

### 3.1 部门负责人绩效原则

- 部门负责人 80% 对本部门核心指标负责。
- 10% 对上游/下游协同质量负责。
- 10% 对跨部门整改、组织贡献、人才培养负责。
- 指标上升但投诉、退款、毛利、交付质量同步恶化，不应视为健康成功。

## 4. 部门内部岗位责权利与协同逻辑

本章是给全栈开发团队理解业务用的岗位级说明。开发时不要只理解"部门"，还要理解部门内部角色之间谁负责生产、谁负责审核、谁负责承接、谁负责监督、谁享受收益、谁承担风险。

> **开发理解重点**：同一部门内部也存在角色分工。例如新媒体中心不是一个岗位，而是由 IP自然流、投流直播、轻创陪跑、编导、拍摄剪辑、客资运营等共同构成。系统页面、权限、数据看板、今日待办和绩效统计必须能体现这些差异。

### 4.1 新媒体与客资中心：三部业务逻辑与岗位分工

新媒体与客资中心是客资生产与客资质量经营部门。它不是单纯"发视频的部门"，而是公司前端增长入口。三个新媒体部门独立核算，但必须使用统一客资口径、统一客资状态、统一成交和退款口径。

| 板块 | 业务逻辑 | 主要岗位 | 关键指标 | 权限边界 |
|---|---|---|---|---|
| 新媒体一部：IP自然流获客 | 与IP老师/专业老师联合，通过抖音、小红书、视频号等自然流账号持续输出专业内容，获取高信任客资。 | 新媒体运营、IP老师助教、账号运营、剪辑拍摄协同 | 客资数、有效率、成交率、内容产能、IP账号增长、7日退款率 | 可提交客资和补充信息；不可越权承诺价格、证书、就业结果；不可私自收款 |
| 新媒体二部：投流/直播/官方成交 | 企业官号、投流、信息流、直播承接和在线成交，承担直播GMV和ROI。 | 投流运营、直播运营、主播/IP老师、场控、客服/助教 | 直播GMV、投流ROI、体验课订单、正课订单、客资成本、7日退款率 | 体验课给销售，正课给报名履约；直播承诺必须符合产品边界 |
| 新媒体三部：轻创陪跑/学员账号增长 | 陪跑轻创学员做账号定位、内容发布、客资产出和收益转化，是未来MCN化的前置部门。 | 轻创陪跑运营、编导、账号教练、客资运营、共享剪辑拍摄 | 轻创学员活跃率、账号定位完成率、内容发布达标率、客资数、有效率、成交率、学员收益达成率 | 可指导学员补充客资信息和协助促成；不得让学员私自承诺、私收款或绕开系统 |
| 共享拍摄剪辑组 | 为一部、二部、三部提供拍摄、剪辑、素材管理、直播物料支持。 | 拍摄、剪辑、素材运营 | 交付及时率、素材质量、内容产能、返工率 | 不直接拥有客资归属，按项目/账号/部门记录服务贡献 |
| 客资运营与结算岗 | 负责客资判重、分级、结算状态、异议流程、兼职/轻创账号风控。 | 客资运营、结算协同、质控协同 | 重复率、虚假率、异议处理时效、结算准确率 | 可审核客资规则和状态；财务最终确认打款 |

#### 4.1.1 新媒体三部的轻创陪跑岗位逻辑

新媒体三部的核心不是单纯获客，而是把轻创学员训练成可持续产出高质量客资的账号经营者。系统必须能统计每名陪跑运营名下学员的账号表现、客资质量、成交结果和学员收益。

| 岗位 | 责任 | 权限 | 收益/考核 | 风险责任 |
|---|---|---|---|---|
| 轻创陪跑运营 | 指导账号定位、内容方向、发布节奏、客资提交、信息补充、成交协助 | 可查看名下轻创学员账号与客资状态；可补充客资信息；可发起客资异议 | 名下学员账号达标率、客资数、有效率、成交率、学员活跃率、学员收益达成率 | 低质客资、虚假指导、过度承诺、学员流失需承担管理责任 |
| 三部编导 | 负责账号定位、内容选题、脚本方向、数据复盘，帮助学员形成稳定内容模型 | 可查看负责账号内容数据和客资结果；可提出内容调整任务 | 负责账号内容发布达标率、互动率、客资转化率、标杆账号孵化数 | 账号定位错误、内容长期无效需复盘整改 |
| 轻创学员/兼职客资提交人 | 根据公司培训和账号经营提交意向客资，可补充客户信息和协助信任背书 | 可录入客资、查看有限状态、发起异议；不可查看完整隐私和销售内部备注 | 有效客资5-10元基础奖励；成交后按产品类型5%-30%提成；过7日退费期后可提现 | 虚假、重复、高退款、飞单、私收款会扣信用分或冻结账号 |
| 客资运营 | 负责轻创/兼职客资判重、状态、结算、异议、信用分基础记录 | 可处理客资状态和结算前置数据；财务确认最终付款 | 异议处理时效、结算准确率、低质账号识别率 | 漏判重复、错误结算、风控不及时需承担责任 |

#### 4.1.2 新媒体与销售的协同规则

- 新媒体负责客资生产、初筛、来源真实性和客资质量；销售负责承接、首触、跟进和成交。
- 客资方可查看接单时间、首触状态、跟进次数、有效/无效、成交、退款、预计收益/兑现收益等状态；不应查看客户手机号全号、微信全号、完整聊天记录、销售内部策略备注。
- 销售必须在接单模式下2分钟接单、10分钟首触、24小时有效性判定、7日3回访。
- 新媒体可对无效判定、漏接、跟进不足、成交归属发起异议；第一轮销售主管处理，第二轮运营主管与销售主管协同，第三轮质控负责人、新媒体总监、销售负责人共同仲裁。
- 新媒体正式指标不背复购，但总监大盘需要观察后续投诉率和客户生命周期质量标签。

### 4.2 销售转化中心：岗位责权利

| 岗位 | 责任 | 权限 | 关键指标 | 风险责任 |
|---|---|---|---|---|

### 4.5 财务、质控、人力、AI中台的控制线

### 4.6 开发团队需要在系统中体现的岗位级差异

- 同属新媒体中心，不同部门页面不同：一部看IP自然流和账号客资；二部看投流ROI、直播GMV、体验课/正课分流；三部看轻创学员账号、陪跑任务、客资与收益。
- 同属销售中心，销售顾问看个人待办和客户，组长看团队接单、漏单、排名、辅导和抢单/公海。
- 学习规划师看自己学员和服务任务；交付主管看班种、人员负荷、风险学员和复购结果。
- 质控可跨部门看证据链，但普通员工只看与自己相关的质控结论和整改要求。
- 财务可看订单金额、实收、优惠、毛利预留、结算状态；其他岗位不应随意看到毛利和完整结算规则。
- 每个岗位的今日待办、权限、可见字段、可操作按钮都要根据责权利不同做差异化。

## 5. 九个视角的业务推演

| 视角 | 系统设计要求 |
|---|---|
| 客户生命周期视角 | 明确客户从陌生用户到人才库、企业推荐、长期职业成长的每个阶段由谁服务、谁协同、谁可见、谁负责异常。 |
| 内部员工工作流视角 | 每个岗位必须有今日待办，员工完成今日待办应基本代表完成本岗位当日基础职责。 |
| 部门交接视角 | 跨部门动作必须有触发条件、资料清单、响应时限、驳回/补正规则和完成标志。 |
| 责权利视角 | 每个岗位必须匹配责任、权限、收益、风险；不能只背责任没有权限，也不能有收益不承担质量风险。 |
| 组织人才视角 | 系统数据要支持岗位梯队、晋升、淘汰、试用期判断、主管辅导和人才盘点。 |
| 经营指标视角 | 每个关键指标必须有主责部门；多个部门共同影响的指标要明确主责、协同和连带责任。 |
| 员工管理与赋能视角 | 系统不是只用来监督和扣分，还要提供话术、知识库、AI建议、标杆案例、主管辅导和培训任务。 |
| 风险控制视角 | 销售过度承诺、特殊低价、私收款、低质客资、隐私泄露、退款责任、就业承诺等必须留痕、审批和质控。 |
| 生态发展视角 | 一个人可能同时是学员、人才、轻创客资提交人、从业者、导师、代理；系统要支持一人多身份和信用体系。 |

## 6. 客户全生命周期链路

客户全生命周期链路是 AI-CRM 的主干。第一版 MVP 所有模块都围绕这条链路展开。

主链路：客资产生 → 有效客资 → 销售承接 → 首购成交 → 报名履约 → 财务审核 → 学生服务 → 学习/考试结果 → 复购升级 → 就业/人才库 → 企业合作。

| 阶段 | 主责 | 核心动作 | 关键数据 |
|---|---|---|---|
| 内容互动/客资提交 | 新媒体/轻创/兼职/直播/转介绍 | 提交客资、初筛、评级、判重 | 来源、平台、账号、需求、等级、提交人 |
| 销售承接 | 销售顾问 | 2分钟接单、10分钟首触、添加企微、有效判定 | 接单时间、首触时间、有效性、跟进记录 |
| 首购转化 | 销售顾问 | 需求判断、方案推荐、成交录单 | 产品、金额、优惠、服务期、批次、承诺、凭证 |
| 报名履约 | 报名履约中心 | 审核订单、合同、开课、拉群、教材、分班 | 履约状态、驳回/补正、班种、学习规划师 |
| 财务审核 | 财务结算中心 | 到账核对、金额审核、低价/异常标记 | 实收金额、账户、审核状态、退款期 |
| 学习服务 | 学习规划师 | 首次触达、学习规划、服务记录、职业种草 | 学习目标、计划、服务记录、风险标签 |
| 复购升级 | 学习规划师 | 识别复购机会、成交、提交复购订单 | 复购类型、依据、金额、订单状态 |
| 就业/人才库 | 就业指导事业部 | 职业诊断、人才认证、岗位匹配 | 职业目标、技能、证书、授权、推荐记录 |

> **客户体验责任原则**：客户在哪个阶段，面对客户的主服务人承担当阶段体验第一责任；质控负责人承担最终监督责任。销售阶段由销售负责，报名当天由报名履约负责，学习期由学习规划师负责，考试证书由考务协同负责，就业服务由就业指导事业部负责。

## 7. 多入口客户/客资分流机制

真实业务不是单一"新媒体获客→销售成交"路径。学习规划师转介绍、复购、就业指导引流、直播订单、企业推荐、分校/代理、线下活动都可能产生新客资或新订单。因此系统必须设置统一新增入口。

### 7.1 统一新增入口五步判断

1. 是否已有主档案：根据手机号、微信、企微、姓名+城市、身份证后四位等做判重。
2. 当前身份是什么：新客资、老学员、复购客户、转介绍客户、外部求职者、轻创客资、直播订单客户等。
3. 当前状态是什么：未成交、待咨询、已付款待报名、已报名待服务、服务中、待就业、待复购等。
4. 本次录入目的是什么：咨询、报名、复购、就业诊断、企业岗位匹配、转介绍、体验课、正课订单等。
5. 下一步交给谁：销售、报名履约、学生服务、就业指导、企业服务、财务审核或主管审核。

| 录入场景 | 录入人 | 默认去向 | 判断规则 |
|---|---|---|---|
| 新媒体/轻创/兼职未成交客资 | 提交人 | 销售转化中心 | 未付款、需咨询、需判断需求 |
| 学习规划师转介绍新客户 | 学习规划师 | 销售转化中心 | 新人未付款，来源归属学习规划师 |
| 学习规划师复购成交 | 学习规划师 | 报名履约中心 | 已成交/付款，进入订单审核 |
| 直播体验课订单 | 直播运营 | 销售转化中心 | 体验课需要转正课 |
| 直播正课订单 | 直播运营 | 报名履约中心 | 已付款正课，直接办理入学 |
| 就业指导引流求职者 | 就业顾问 | 销售或就业指导 | 买考证/技能给销售；就业服务给就业指导 |
| 企业团培/推荐学员 | 企业合作经理 | 报名履约或销售 | 已签合同给报名；未成交给销售/企业服务 |
| 分校/代理客户 | 分校/代理 | 销售或报名履约 | 未付款给销售；已付款给报名履约审核 |

## 8. 部门交接、审批与责权利机制

所有跨部门动作都必须工单化或流程化。系统要记录发起人、执行人、审核人、确认人、监督人，以及超时、驳回、补正、完成标志。

| 流程 | 触发条件 | 发起 | 接收/审核 | 完成/责任规则 |
|---|---|---|---|---|
| 新媒体客资交销售 | 客资提交/判重成功 | 新媒体/轻创/兼职 | 销售顾问 | 2分钟接单、10分钟首触；无人接单进抢单池/漏单记录 |
| 销售成交交报名 | 客户付款或提交订单 | 销售顾问 | 报名履约 | 5分钟响应；核查项目、金额、服务期、批次、承诺、地址 |
| 报名交学生服务 | 合同/开课/拉群/教材/分班完成 | 报名履约 | 学习规划师/交付主管 | 学习规划师确认接收，生成首次触达任务 |
| 学生服务交考务 | 进入报考/考试节点 | 学习规划师 | 考务专员 | 报考资料、批次、费用、准考证、成绩、证书节点可追踪 |
| 复购订单 | 学员复购成交 | 学习规划师 | 报名履约/财务 | 推荐依据留痕；质控可判定过度营销 |
| 缓考/补考/延期 | 学员提出或需调整批次 | 学习规划师 | 主管→财务→质控→报名 | 完整流程不简化，记录费用、风险、责任和转班结果 |
| 7日退费 | 学员提出或责任人发起 | 当前服务责任人 | 主管→质控→财务 | 1小时响应、3个工作日方案、15日闭环；销售有一次挽回窗口 |
| 客资异议 | 提交人不认可无效判定/跟进质量 | 新媒体/提交人 | 销售主管/运营主管/质控仲裁 | 三轮处理；最终由质控、新媒体总监、销售负责人协同仲裁 |

### 8.1 复杂规则的五层表达

1. 默认规则：系统自动执行，例如90日进公海、7日退款期冻结佣金。
2. 审批例外：特殊低价、特殊承诺、延期、退款、跨部门转交必须审批。
3. 质控判定：投诉、责任、过度营销、交付质量由质控取证判定。
4. 复盘修正：每月由老板、业务负责人、人力、质控、财务看数据调整规则。
5. 责权利备注：明确谁发起、谁执行、谁确认、谁监督，方便系统留痕与开发实现。

### 9.1 流程引擎能力

- 自动触发：客资分配、首触、回访、订单审核、首次触达、学习规划、考试节点等。
- 人工发起：员工可发起订单、工单、审批、投诉、转介绍、复购、缓考申请。
- 审批、驳回、补正：审批人必须填写原因和补正要求。
- 超时提醒与临时提醒：提醒本人、主管或团队，并记录是否影响绩效。
- 信息补充：有权限角色可对客户、订单、学员、工单补充信息，系统记录补充人、时间和可见范围。
- 责任记录与状态追踪：记录发起、执行、审核、确认、监督，以及待处理、处理中、待补正、已完成、已超时等状态。
- 数据进入绩效：关键动作、超时、质量评分、投诉、工单完成情况进入后续绩效统计。
- 备注分级与权限可见：客户隐私、毛利、质控判定、员工绩效等按角色权限展示。

## 10. 数据档案体系

系统采用"一主档案，多部门补充"的档案体系。一个人只应有一个客户主档案，客资、订单、学员、职业、人才等身份都挂在同一主体上。

| 档案类型 | 关键字段 | 主要补充部门/岗位 |
|---|---|---|
| 客户主档案 Person | 姓名/称呼、手机号、微信/企微、城市、学历、职业、多身份标签、风险标签、隐私授权 | 客资提交人、销售、报名、学习规划师、就业指导 |
| 客资档案 Lead | 来源、平台、账号、提交人、初步需求、等级、判重、分配、接单、有效性、异议 | 新媒体/提交人、销售、主管 |
| 客户跟进档案 | 跟进方式、沟通摘要、意向等级、下次回访、预计成交、成交阻碍 | 销售顾问 |
| 订单档案 Order | 订单类型、产品、金额、优惠、服务期、考试批次、成交人、来源人、凭证、承诺、退款期 | 销售/学习规划师/报名/财务 |
| 学员档案 Student | 已购项目、服务期、班种、学习规划师、学习阶段、首次触达、学习规划状态 | 报名履约、交付主管、学习规划师 |
| 学习服务档案 | 学习计划、电话/私聊记录、学习进度、问题工单、职业种草、复购机会 | 学习规划师、学务支持 |
| 考务档案 | 计划批次、当前批次、报考资料、费用、准考证、成绩、证书、缓考/补考记录 | 考务、学习规划师、财务 |
| 职业发展档案 | 职业目标、职业偶像、测评结果、直播观看、诊断预约、职业规划建议、就业产品购买 | 学习规划师、就业指导 |
| 人才库档案 | 人才等级、证书、成绩、技能标签、项目案例、平台评价、授权状态、推荐记录 | 就业指导、考务、学员授权 |
| 员工绩效档案 | 岗位、部门、今日待办、业绩、服务质量、投诉、培训、主管辅导、预警 | 系统、人力、质控、主管 |

### 10.1 字段管理原则

- 阶段必填：每个阶段只强制填写该阶段必要字段，避免一线员工表单负担过重。
- 缺失提醒：档案不完整不一定阻断流程，但系统提醒责任部门补充。
- 敏感字段分权：手机、微信、身份证、证书原件、毛利、绩效备注、质控记录分权限可见。
- 修改留痕：关键字段修改记录修改人、时间、修改前后内容。
- 审核字段锁定：财务审核、质控判定、合同、订单金额等审核后不能随意改。
- 一人多身份：一个主体可同时是学员、人才、轻创提交人、导师、代理等。
- 档案完整度评分：每个学员/客户有档案完整度，归属对应部门补齐。

## 11. 老板客户全生命周期经营大盘

老板经营大盘应以客户全生命周期漏斗为核心，不是堆砌散乱指标。老板需要看到客户从哪里来、在哪一步流失、哪个部门承接慢、哪个产品赚钱、哪个服务阶段出问题、最终是否复购和实现职业发展。

| 链路节点 | 核心指标 | 经营意义 |
|---|---|---|
| 客资产生 | 客资总数、新增客资数、重复客资数、无效客资数 | 看前端供给 |
| 客资质量 | 有效客资数、有效客资率、A/B/S级占比 | 看客资质量 |
| 销售承接 | 2分钟接单率、10分钟首触率、漏单数、添加成功率 | 看销售速度 |
| 销售转化 | 成交笔数、成交金额、成交率、客单价、7/30/90日成交率 | 看首购能力 |
| 报名履约 | 对接订单数、通过笔数、驳回笔数、当日履约率、特殊承诺数 | 看履约启动 |
| 财务审核 | 审核订单数、通过笔数、驳回笔数、到账金额、异常订单数、预估毛利 | 看钱和利润 |
| 学生服务 | 新入学人数、在学人数、首次规划完成率、触达完成率、风险学员数 | 看服务承接 |
| 学习/考试 | 达标人数、结业人数、异常结业人数、弃考、缓考、通过人数 | 看交付结果 |
| 复购升级 | 复购笔数、复购金额、复购率、畅学卡转化、转介绍数 | 看生命周期价值 |
| 就业发展 | 职业诊断数、就业服务成交、人才库认证数、推荐企业数、入职/兼职完成数 | 看生态进展 |

### 11.1 老板大盘页面建议

- 经营总览：首页展示今日业绩、本周业绩、本月业绩、净收入、预估毛利、人效、退款、投诉。
- 客户全生命周期漏斗：客资→有效→销售→成交→报名→财务→入学→学习规划→复购。
- 部门贡献排行：客资、成交、复购、退款、投诉、人效。
- 产品经营排行：报名人数、成交金额、毛利、退款率、复购贡献、服务结果。
- 服务与交付质量：入学、在学、结业、异常结业、弃考、缓考、通过、投诉、风险学员。
- AI异常与建议：哪里异常、哪个部门需要处理、哪个产品风险高、哪个指标连续下降。

## 14. 核心对象关系与数据库表草案

> **关键设计判断**：Person 是核心，不是 Lead。Lead 是一次机会，不是一个人。Order 是成交事实。StudentProfile 是服务身份。Task 是每日工作的驱动器。

| 核心对象 | 说明 |
|---|---|
| User/Department/Role | 员工、部门、角色权限，决定登录、菜单、数据可见、任务归属和业绩归属。 |
| Person | 客户主档案，一个人只应有一个主档案，支持一人多身份和判重合并。 |
| Lead | 客资或机会，记录来源、等级、分配、接单、有效性、成交状态。一个 Person 可有多个 Lead。 |
| FollowUp | 销售跟进记录，支持7日3回访、下次回访、意向等级和质控复查。 |
| Order | 订单，所有首购、复购、直播正课、就业服务、未来企业团培都应形成订单。 |
| Product/ClassBatch | 产品和班种，用于订单、分班、考试批次、学习期和统计。 |
| StudentProfile | 学员档案，订单审核通过并履约后生成，绑定学习规划师、服务期和班种。 |
| ServiceRecord | 学习规划师服务留痕，包括首次触达、学习规划、电话、私聊、职业种草、风险处理。 |
| FinanceReview | 财务审核记录，关联订单，记录到账、驳回、7日退款期、毛利预留。 |
| Task/Workflow | 任务和流程，支持今日待办、审批、驳回、补正、超时、临时提醒、责任追踪。 |
| AuditLog | 操作日志，记录谁在什么时间修改了什么，关键动作不可缺失。 |

## 17. 开发配合与业务培训机制

三位开发师都是全栈开发，业务逻辑需要在开发中快速内化。老板前期兼任产品负责人是合理的，但要通过机制把业务理解沉淀给 AI应用开发部，而不是所有问题长期卡在老板。

### 17.1 项目配合机制

- 每日 15-30 分钟短会：昨天完成什么、今天做什么、哪个业务逻辑不懂、是否影响上线。
- 每周 60-90 分钟模块验收：拉对应业务负责人参与，不要只让老板和开发闭门验收。
- 业务规则答疑池：所有开发疑问统一记录问题、当前理解、拍板人、最终答案，形成业务知识库。
- 需求变更池：所有新增需求先进入池子，分为必须本期做、上线后补、二期再说。
- 模块 Owner 制：开发师 A 负责客资+销售，开发师 B 负责订单+财务，开发师 C 负责学生服务+大盘+流程任务。
- 技术负责人统一数据库规范、API风格、权限体系、状态枚举、代码规范、部署方式。

### 17.2 业务培训安排

| 培训 | 主题 |
|---|---|

## 18. 附录：字段、状态、规则与二期池

### 18.1 关键状态枚举建议

| 对象 | 状态/定义 |
|---|---|
| Lead 客资状态 | 待分配、待接单、跟进中、有效、无效、已成交、沉睡、公海 |
| Order 订单状态 | 待报名审核、待补正、报名通过、报名驳回、待财务审核、财务通过、财务驳回、已履约、已退款 |
| Student 学员状态 | 待触达、待规划、学习中、冲刺期、服务期、结业、异常 |
| Task 任务状态 | 待处理、处理中、已完成、已超时、已取消 |
| Workflow 流程状态 | 待处理、处理中、待补正、已驳回、已通过、已关闭 |
| 客资等级 | D 未判断；C 需求弱/间接推荐；B 30天内成交；A 7日内成交；S 当日可成交 |

### 18.2 二期需求池

- 完整就业事业部系统：职业诊断、就业产品、导师、岗位、推荐、招聘会。
- 人才库与企业端：人才认证、企业脱敏查看、授权机制、企业会员、企业岗位发布。
- 轻创/兼职结算：预计收益、兑现收益、提现金额、自动财务审核、信用分。
- 完整绩效自动核算：岗位绩效、主管辅导、晋升淘汰预警、申诉流程。
- 完整毛利模型：考试成本、客资成本、课程成本、导师成本、服务成本、项目利润。
- 深度集成：企业微信聊天同步、课程平台、题库系统、支付系统、短信/通知。
- AI能力：AI跟进建议、AI职业规划、AI质控摘要、AI经营分析、AI学习助手。
- 外部产品：AI题库工具、健康行业从业者客户管理工具平台。

### 18.3 给开发团队的最终提醒

- 不要把 Lead 当成客户主档案，Person 才是核心。
- 所有钱和服务必须围绕 Order 流转。
- 所有员工今日待办必须来自 Task，而不是页面散落状态。
- 所有跨部门动作尽量进入 Workflow 或至少有状态和责任记录。
- 所有关键修改进入 AuditLog。
- 第一版要快，但权限、状态、日志、主链路不能偷懒。
