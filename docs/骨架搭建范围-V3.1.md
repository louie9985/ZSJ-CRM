# 骨架搭建范围 V3.1（X 极简骨架）

> **文档性质**：monorepo 骨架的工程执行计划（范围边界与出口标准）。**非受控文档**，不进入总纲/开发手册/事件契约表的变更流程；供后续会话接续开工。
> **状态**：✅ **已搭建完成**（2026-07-08）。范围定稿（2026-07-08 商定），出口标准全部通过。
> **事实源**：仓库结构与边界铁律以《技术选型-V3.2》《开发手册细则-V3.1》《CLAUDE.md》为准，本文只界定"第一步搭骨架"的范围。
> **定位**：技术选型定稿后的第一个工程动作——先立结构与管道，再进 B1 实现。

---

## 0. 方向定性：X 极简骨架

**只搭结构与管道，不碰任何业务逻辑。** 天然避开红类纪律（金额/佣金/Ownership/状态机/权限/审批/迁移脚本/定时任务全部不涉及），骨架阶段无红类产出，走绿类走查 + CI 门禁即可。

**否决 Y 方案**（朝 PRD-B1 出口靠拢）：那等于直接进入 B1 平台底座实现，与"先立骨架、后填业务"的目的冲突，且会过早触发红类纪律。

## 1. 本轮做（7 项）

| # | 项 | 具体范围 |
|---|---|---|
| ① | **monorepo** | pnpm workspace + Turborepo；**仅建 `packages/shared-core` + `apps/server`**，`packages/web`、`packages/mobile`、`packages/h5-partner` **本轮不建** |
| ② | **server 骨架** | NestJS 壳 + `platform/` 和 `modules/` 空目录占位 + `/health` 端点 + 统一响应拦截器 `{code,message,data,trace_id}` + X-Request-Id 中间件骨架（**只透传，不去重**） |
| ③ | **shared-core 骨架** | 目录占位 + 一个共享示例（证明 `apps/server` 能跨包引用 `packages/shared-core`） |
| ④ | **Docker Compose** | `pg16 + redis7 + rabbitmq + nginx + app`，一条 `docker compose up` 起全套 |
| ⑤ | **Prisma 接入** | **不建表、不迁移**；只配 `datasource` / `generator` |
| ⑥ | **ESLint boundary** | 边界铁律拦截：`platform/**` 禁 import `modules/**`；`modules/mX` 禁 import `modules/mY`；`web/mobile/h5` 禁写业务逻辑（本轮无这些包，规则先就位） |
| ⑦ | **CI 门禁** | lint + tsc + test + boundary 检查，全绿方可合入 |

---

## 2. 本轮明确不碰

- **前端三端**（web / mobile / h5-partner）——连目录都不建。
- **任何数据表 / Prisma 迁移**——迁移脚本禁止 AI 直接生成合入（宪法），骨架阶段一律不碰。
- **鉴权**——**连 mock 都不放**。
- **业务模块 m1~m13**——目录占位即止，不写任何模块逻辑。
- **红类逻辑**——金额/佣金/Ownership/状态机/权限/审批/定时任务，一律零涉及。
- **极光 / COS / 事件消费者真实现**——RabbitMQ 只起容器，本轮不接 dispatcher / 消费者；COS 不接；`WecomPushService` 不实现。

---

## 3. 出口标准（验收即通过）

1. `docker compose up` 起全套服务（pg + redis + rabbitmq + nginx + app）。✅ 五服务均 Up，pg/redis/rabbitmq healthy
2. `/health` 返回 200。✅ 经 nginx `:8080/health` 与 `/api/v1/health` 均 200，响应信封 `{code:0,message:"ok",data:{status:"ok"},trace_id}` 正确
3. `pnpm -w lint && pnpm -w tsc && pnpm -w test` 全绿。✅ lint/tsc/test 三门禁 Tasks 全 successful
4. 越界 import（如 `platform` 引 `modules`）被 CI boundary 检查拦下。✅ 已实测三条不变量：module→module 拦、platform→module 拦、同模块内互引放行
5. `packages/shared-core` 能被 `apps/server` 正常引用（共享示例可跑通）。✅ `ResponseInterceptor` 引用 shared-core 的 `ok()`，端到端跑通
