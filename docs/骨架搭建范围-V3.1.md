## 0. 方向定性：X 极简骨架

**只搭结构与管道，不碰任何业务逻辑。** 天然避开红类纪律（金额/佣金/Ownership/状态机/权限/审批/迁移脚本/定时任务全部不涉及），骨架阶段无红类产出，走绿类走查 + CI 门禁即可。

**否决 Y 方案**（朝 PRD-B1 出口靠拢）：那等于直接进入 B1 平台底座实现，与"先立骨架、后填业务"的目的冲突，且会过早触发红类纪律。

## 2. 本轮明确不碰

- **前端三端**（web / mobile / h5-partner）——连目录都不建。
- **任何数据表 / Prisma 迁移**——迁移脚本禁止 AI 直接生成合入（宪法），骨架阶段一律不碰。
- **鉴权**——**连 mock 都不放**。
- **业务模块 m1~m13**——目录占位即止，不写任何模块逻辑。
- **红类逻辑**——金额/佣金/Ownership/状态机/权限/审批/定时任务，一律零涉及。
- **极光 / COS / 事件消费者真实现**——RabbitMQ 只起容器，本轮不接 dispatcher / 消费者；COS 不接；`WecomPushService` 不实现。

## 6. Web 极简壳（历史记录，已被 CR-12 替代）

延续 X 骨架"只立结构与管道、不碰业务/鉴权/红类"定性，仍属绿类。

**本轮做（6 项）**：
| # | 项 | 落地 |
|---|---|---|
| ① | `packages/web` 建包 | Vite6 + React18 + TS + antd5 + ProComponents + react-router7，纳入 pnpm workspace + turbo pipeline |
| ② | 布局壳 + 路由骨架 | ProLayout 外壳 + 占位首页（/home）+ 404，路由表就位，**不填业务菜单** |
| ③ | API 请求层 | `shared-core/http.ts` 统一封装（解信封 `{code,message,data,trace_id}` + 透传 `X-Request-Id`，纯 fetch 无 DOM 依赖、Taro 兼容）+ TanStack Query Provider + Vite dev proxy → `/api/v1` |
| ④ | server 接 Swagger | `@nestjs/swagger` 挂 `/api/v1/docs`；`OPENAPI_EXPORT` 环境变量走导出模式出 `openapi.json`；仅 `/health` 有装饰，**不碰业务/迁移** |
| ⑤ | OpenAPI 出码管道 | `shared-core` 用 `openapi-typescript` 从 `openapi.json` 生成 `src/api/schema.ts`；web 消费生成类型（`components['schemas']['HealthData']`），端到端"server 出码 → shared-core 生成 → web 使用"跑通 |
| ⑥ | boundary + CI 纳入 web | ESLint `no-restricted-imports` 拦 `web → @zsj/server`；CI 增 OpenAPI 出码步骤 + web build |

**本轮不碰**：业务模块页面、登录鉴权页（连 mock 不放）、ECharts 具体图表、`packages/mobile`、`packages/h5-partner`（仍不建）、任何数据表迁移、真实业务 mock。

**出口标准（全部实测通过）**：
1. ✅ `pnpm --filter @zsj/web dev` 起 web（:5173），ProLayout 壳 + 占位页可见
2. ✅ web 经 dev proxy 调 `/api/v1/health` 返 200、信封正确解出（实测经 :5173 代理拿到 `{code:0,...,trace_id}`）
3. ✅ server `/api/v1/docs`（HTML 200）+ `/api/v1/docs-json` 可导出 openapi
4. ✅ OpenAPI 出码管道跑通：server 导出 → shared-core 生成 `schema.ts`（含 HealthData/HealthResponse）→ web 引用消费
5. ✅ `pnpm -w lint && pnpm -w tsc && pnpm -w test`（含 web）全绿
6. ✅ boundary 拦截 `web → @zsj/server` 越界 import（探针实测被拦）

**踩坑记录（非显然）**：
- web 消费 shared-core **走 TS 源码 alias**（`vite.config.ts` resolve.alias → `shared-core/src/index.ts`），不走 `dist`：shared-core 输出 CJS（`Object.defineProperty` 具名导出）供 Nest 用，Rollup 静态分析 workspace 链接包时解析不到具名导出报 `"request" is not exported`；直连 TS 源交由 esbuild 编译，免 CJS interop、免"web build 依赖 shared-core 先 build"的顺序耦合。
- OpenAPI 生成产物用 **`schema.ts` 而非 `schema.d.ts`**：tsc 不会把纯 `.d.ts` 输入拷进 `dist`，导致 `index.d.ts` 引用的 `./api/schema` 在 dist 缺失；改 `.ts` 后 tsc 正常 emit `dist/api/schema.{js,d.ts}`。
- `openapi.json` 为中间产物**不入库**（server 导出，`.gitignore` 忽略）；生成的 `schema.ts` **入库**（可复现类型源）。
- server 导出模式复用 `main.ts`：`OPENAPI_EXPORT` 环境变量存在时构建 document、`writeFileSync` 后 `app.close()` 退出，不 listen 端口（CI 无需起 DB 即可出码）。
