# 第一阶段认证范围

- 状态：已批准
- 日期：2026-08-04
- 架构依据：ADR-0034

## 已知事实

- 当前只有 `apps/workbench-web` 一个 Web 制品，提供 PC、员工移动和兼职入口。
- 员工 PC 与移动页面共用 `pc` surface；兼职使用独立 `part-time` surface。
- 账号和 Argon2id 密码凭证由 `workforce-access` 持有；人员、Employment、Assignment 由 `organization` 持有；固定角色与 Permission 判定由 `authorization` 持有。
- API 应用层的 `AccountAccessApplicationService` 是唯一认证协调入口，各模块不得跨表查询。
- 浏览器只持有独立的 HttpOnly 不透明 Session Cookie，不接收密码 hash、JWT 或服务端 Redis 索引。

## 交付范围

第一阶段交付用户名或手机号加密码登录、会话查询、密码重新认证、当前 Assignment 选择与注销。Session idle 为 30 分钟、absolute 为 8 小时，同账号同 surface 并发上限为 1；登录、重新认证、Assignment 切换和敏感操作后轮换。

认证错误固定为 `authentication_invalid_credentials`、`authentication_required`、`authentication_csrf_rejected`、`authentication_rate_limited`、`authentication_dependency_unavailable`。账号不存在、密码错误和账号禁用不得产生可区分响应。

## 禁止假设

- 不支持 MFA、自助找回、外部用户、邀请访问、企业微信/微信登录、第三方联合身份或非浏览器客户端。
- 不为未来 JWT 创建端点、密钥、表或不可达代码。
- 不通过手机号、姓名、部门、岗位、角色名称或客户端路由自动关联身份或授予权限。
- 不把 Session 存在解释为最终业务授权；每次受保护操作仍重新解析有效组织上下文并执行 Permission 判定。

## 非目标

本文不定义 CRM 业务角色、数据权限、审批规则或外部访问模型。真实非浏览器客户端出现后，JWT 方案必须另立 ADR。
