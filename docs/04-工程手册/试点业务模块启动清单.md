# 试点业务模块启动清单

本清单落实 ADR-0029。它允许一个已确认的业务模块在本地开发，不授权预发布、生产、真实外部 Provider 或真实业务数据。

## 开始编码前

- [ ] 项目负责人指定唯一试点模块名称、业务 Owner 和模块代码 Owner。
- [ ] 在 `docs/02-业务规则/` 新建经 Owner 确认的规则文件，写明版本和生效时间。
- [ ] 定义唯一业务对象、标识、最小纵向流程和明确非目标。
- [ ] 定义状态、合法迁移、撤销、退回、重开、冲突处理和历史保留。
- [ ] 定义内部用户、功能权限、数据范围及所有拒绝路径；未知权限默认拒绝。
- [ ] 定义模块拥有的数据、Prisma schema、迁移方案和可逆/恢复指导；禁止跨模块直接查询表。
- [ ] 在 `contracts/` 先完成 HTTP、Event 和 Job 合同评审；定义版本、错误码、幂等键和兼容策略。
- [ ] 定义审计动作、最小安全 Trace 属性及不得记录的敏感字段。
- [ ] 明确是否接入 Form、File、Task、Notification、Workflow 或外部访问；未确认的能力不实现。
- [ ] 定义合成本地测试数据、单元/合同/集成/E2E 验收场景和故障/重试/重复请求场景。
- [ ] 在任务 handoff 记录已知事实、允许假设、禁止假设、非目标、路径 Owner 和未决问题。
- [ ] 项目负责人确认该模块仅在本地开发运行，且不承载真实业务数据。

## 实现与合并门

- [ ] 领域代码仅依赖 `platform-sdk`、公共入口和已评审合同；无深导入、供应商 SDK 或跨模块数据库访问。
- [ ] 写入命令经过 Organization/Authorization，产生适当 Audit，并定义幂等、事务、超时、重试和恢复行为。
- [ ] 迁移是版本化 Prisma SQL，历史迁移不修改；记录回退或恢复指导。
- [ ] 所有新行为有测试覆盖，模块级独立 Review 覆盖授权、幂等、事务、迁移、可观测与兼容性。
- [ ] `pnpm check` 通过，且不把本地结果写成预发布或生产证据。

## 进入非本地环境前

- [ ] G5 外部证据完成并经独立复审：受信镜像、预发布发布/回滚、主机、COS/Sentry、恢复演练和正式签收。
- [ ] 试点模块完成其自身的发布授权、真实数据治理、运行告警和部署验收；G5 通过不自动替代这些模块级条件。
