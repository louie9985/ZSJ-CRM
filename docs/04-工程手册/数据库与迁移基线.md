# 数据库与迁移基线

- 状态：Prisma 基线已实现；真实 PostgreSQL 空库重建与结构差异验证仍是环境验收门
- 适用范围：应用 PostgreSQL、Prisma Schema、Repository、事务和迁移
- 架构依据：ADR-0028；ADR-0011 中未被替代的 PostgreSQL 与治理约束

## 开源与自研边界

- PostgreSQL、Prisma ORM、Prisma CLI 和批准的 PostgreSQL 驱动使用开源实现。
- `packages/database`、模块 Repository、Unit of Work、错误映射和迁移治理由项目自研。
- 自研部分只定义项目边界和运行规则，不复制数据库、ORM、驱动或连接池功能。

## 目录原则

- `packages/database`：连接、事务、迁移执行、健康检查和测试工具。
- `packages/crm-modules/<module>`：该 CRM 核心模块私有的 Prisma Schema 源片段、Repository 与映射器。
- `packages/domain-modules/<module>`：边界确认后，该领域模块私有的 Prisma Schema 源片段、Repository 与映射器。
- `scripts/migration`：迁移校验、执行、回填和恢复辅助工具。

不得建立汇总全部业务能力的公共数据层，也不得从其他模块导入 Prisma Schema 片段、生成类型、查询参数或 Repository。部署 Schema 可以确定性组合，但它只是生成和迁移输入，不授予跨模块访问权。

## 每个数据库变更必须提供

1. 所有模块、变更目的和兼容的应用版本范围。
2. 经评审的 Prisma migration SQL 和更新后的模块 Prisma Schema 源片段；无法由 Prisma 表达的 PostgreSQL 对象必须在 SQL 与元数据中明确列出。
3. 锁表、耗时、磁盘、连接和复制影响评估。
4. 旧版本应用与新结构并存时的兼容说明。
5. 回滚应用、前滚修复、数据恢复或备份点说明。
6. 数据回填的幂等、断点续跑、限速和进度观测方案。
7. 从空库及当前基线升级的迁移测试。

## 执行纪律

- 迁移必须是单独部署步骤，不随 API 或 Worker 启动自动运行。
- 迁移使用专用 DDL 凭据和全局互斥；应用运行时账号不拥有 DDL 权限。
- 已执行迁移不可修改，修复以新迁移追加。
- 共享环境禁止使用 `prisma db push` 或自动 Schema 同步；`prisma migrate dev` 只用于隔离开发库生成候选迁移。
- 破坏性迁移先完成兼容代码、回填和读写切换，再在后续版本删除旧结构。
- 迁移失败时先判断应用兼容性和数据状态，不机械执行可能丢失新数据的 Down Migration。

## 上线前检查

- SQL 与执行计划已评审，Raw SQL 使用参数化输入。
- 备份或恢复点可用，恢复步骤已验证。
- 长事务、并发 DDL 和锁等待风险已在接近真实数据量的环境验证。
- 迁移、应用回滚和前滚修复的负责人及停止条件明确。
- 指标与告警能观察迁移状态、连接池、错误、死锁、慢查询和数据库容量。

## 当前命令与迁移期约束

根 `pnpm db:migrate` 当前仍是历史 SQL 的部署迁移入口。它组合 `packages/database/migrations` 与 `packages/crm-modules/*/migrations`，按全局十位版本号排序后在同一 advisory lock 下执行；模块目录发现顺序不能改变迁移顺序。Prisma 重构完成前不得移除这条历史重建能力。

- `DATABASE_MIGRATION_URL_FILE=<path> pnpm db:migrate`：使用专用迁移连接执行版本化 SQL。连接字符串只从文件读取，不接受命令行值。
- 迁移文件位于拥有包的 `migrations/`，名称为十位全局递增编号、下划线描述和 `.sql` 后缀；同名 `.meta.json` 必须记录 Owner、目的、兼容范围、锁与数据影响、回填、破坏性标记、恢复和前滚修复指导。破坏性迁移还必须记录明确批准。
- 执行器使用 PostgreSQL Advisory Lock，校验已执行迁移 Checksum，并仅在迁移事务成功后写入 `ai_crm_migrations.applied_migrations`。
- API 和 Worker 启动不得调用迁移命令；共享环境禁止 `prisma db push`。

项目 SQL Runner 保持唯一生产迁移入口。Prisma Schema/CLI 产生候选差异，评审后的 SQL 必须转换为项目全局十位编号和 metadata 后才可部署；不得直接使用 `prisma migrate dev/deploy` 建立第二套历史，不得伪造记录或重写历史 SQL。
