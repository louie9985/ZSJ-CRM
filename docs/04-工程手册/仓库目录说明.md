# 仓库目录说明

> 本文档用于同步维护仓库目录、技术栈和职责边界。新增、重命名或拆分目录时，应同时更新本文档与相关目录下的 `README.md`。

## 总览

| 目录 | 技术栈 | 主要职责 |
|---|---|---|
| `apps/` | NestJS、React、Taro、Vite | 独立可运行应用：API、Worker、PC 工作台、内部移动端、外部端 |
| `packages/` | TypeScript、Prisma、Pino、OpenAPI 生成客户端 | 公共能力包：配置、数据库、可观测性、平台 SDK、平台模块、共享 UI |
| `contracts/` | OpenAPI、AsyncAPI、JSON Schema | HTTP、事件、Job、权限、配置、文件、通知等契约 |
| `deploy/` | Docker Compose、Nginx、Keycloak、Flowable | 本地、测试、生产部署与运行时配置 |
| `scripts/` | Node.js 脚本 | 检查、构建、部署、迁移、契约生成、引导 |
| `tests/` | Vitest、Node.js、Docker、浏览器自动化 | 契约、集成、安全、E2E、测试夹具 |
| `docs/` | Markdown | 权威基线、业务规则、模块说明、工程手册、ADR、验收与安全治理 |
| `references/` | Markdown、外部资料 | 非权威参考、调研记录、供应商材料 |
| `prisma/` | Prisma | 根级数据库 schema 组合与基础定义 |
| `.github/` | GitHub Actions | CI 与仓库自动化 |

## 顶层目录

### `apps/`

| 目录 | 技术栈 | 功能 |
|---|---|---|
| `apps/api` | NestJS + TypeScript + Redis + OIDC | 同步 HTTP API、BFF 登录会话、平台模块编排 |
| `apps/worker` | NestJS + TypeScript + RabbitMQ + COS + ClamAV | 异步消费、Outbox/Inbox、文件校验与扫描 |
| `apps/workbench-web` | React 19 + Vite + Ant Design + Pro Components | PC 工作台前端 |
| `apps/internal-mobile` | Taro + React 18 + NutUI React | 内部移动端 H5 |
| `apps/external-portal` | Taro + React 18 + NutUI React | 外部端 H5 / Weapp |

### `packages/`

| 目录 | 技术栈 | 功能 |
|---|---|---|
| `packages/api-client` | 生成式 TypeScript 客户端 | OpenAPI 客户端，分内外部版本 |
| `packages/config` | TypeScript | 环境变量、Secret 文件、启动配置校验 |
| `packages/database` | Prisma + PostgreSQL | 数据库运行时、迁移兼容检查、持久化基础 |
| `packages/observability` | Pino + OpenTelemetry + Sentry | 日志、Trace、错误、健康检查 |
| `packages/platform-sdk` | TypeScript SDK | 平台能力客户端与统一调用入口 |
| `packages/shared-ui` | React | 跨应用复用 UI 组件 |
| `packages/test-config` | Vitest 配置 | 公共测试配置 |
| `packages/tsconfig` | TypeScript 配置 | 统一编译基线 |
| `packages/eslint-config` | ESLint | 统一 lint 与边界规则 |
| `packages/domain-modules` | 预留目录 | 已确认业务域模块的未来承载区 |

## 生成物与缓存

以下目录通常不作为人工维护的功能目录：

- `dist/`
- `coverage/`
- `node_modules/`
- `.turbo/`
- `output/`
- `*.tsbuildinfo`

## 维护规则

1. 新增、重命名、删除目录时，同步更新本文档。
2. 新增应用或公共包时，优先补充对应 `README.md`。
3. 生成物目录不要写入业务职责说明。
4. `references/` 只放非权威材料，不得覆盖 ADR、合同或已确认业务规则。
